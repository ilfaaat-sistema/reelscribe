# ТЗ 01. Задания вместо россыпи сессий импорта

**Статус:** ТЗ

## Проблема / цель

История импортов — плоский список из 29 сессий, где 14 пустых (следы неудачных попыток), а
остальные названы невнятно: «Партия 02 из 4», «Пробная партия 25», семь строк вообще без
комментария. Через две недели по нему невозможно понять, что за партию разбирали — владелец на
этом и споткнулся: «я не помню, какую папку мы парсили».

Цель: свести историю к двум понятным заданиям, показать у каждого рилса его происхождение
(откуда пришёл и когда добавлен) и сделать так, чтобы будущие импорты не расползлись снова.

### Что показал разбор источников (замеры, не оценки)

Основной массив разобранного пришёл **не из сохранённых папок, а из личной переписки**: в диалоге
с профилем `neyro_set7` лежит 766 ссылок, 667 из них уже в базе. Пять сохранённых папок со словом
«нейросети» — «Нейросети» (79), «ИИ нейросети» (312), «Нейросети для фото и видео» (41),
«Повторить про нейросети» (36), вторая «Нейросети» (35) — дают ещё 496 ссылок, но разобрано из них
только 48.

| Источник темы «Нейросети» | Ссылок | В базе | Не заведено |
|---|---|---|---|
| Диалог `neyro_set7` | 766 | 667 | 99 |
| Пять папок «нейросети» | 496 | 48 | 448 |
| **Итого (пересечение 53)** | **1209** | **668** | **541** |

Остальные 36 рилсов базы — 13 из июньского `Копия reels_list.csv` и 23 ручных теста; расшифровано
из них 3. В основном задании — 582 расшифровки и 86 «без аудио».

## Пользовательский сценарий

1. Владелец открывает главную и видит вместо ленты сессий две карточки: «Нейросети» (668 рилсов,
   582 расшифровки) и «Остальное» (36).
2. Клик по карточке открывает таблицу только этого задания; внутри карточки при желании
   раскрывается список её сессий импорта — пустые не показываются.
3. В таблице у каждого рилса видно, откуда он: `neyro_set7` или название папки, и когда добавлен.
   По дате добавления можно сортировать.
4. При новом импорте владелец выбирает задание из списка или заводит новое — ссылки сразу попадают
   в нужную группу.

## Функциональные требования

1. Две группы: **«Нейросети»** — всё из диалога `neyro_set7` и из сохранённых папок, в названии
   которых есть «нейросети» или «ИИ»; **«Остальное»** — всё прочее.
2. Принадлежность хранится в БД у рилса, а не только у сессии.
3. Пометки происхождения у каждого рилса: вид источника, имя источника, дата добавления.
4. Фильтр по заданию в списке рилсов и в экспорте.
5. Выбор задания в форме импорта (существующее из списка либо новое).
6. Сессии с нулём рилсов в интерфейсе не показываются; из базы **не удаляются**.

## Модель данных и контракт имён

Метка живёт **у рилса**, а не только у сессии: `shortcode` дедуплицируется, один рилс приходит из
разных сессий, и по сессии его происхождение не определить (июньская сессия на 290 рилсов на 96%
состоит из ссылок, которые есть и в переписке).

```sql
alter table public.reels add column if not exists collection  text;
alter table public.reels add column if not exists source_kind text;   -- директ | папка | лента
alter table public.reels add column if not exists source_name text;   -- neyro_set7 | названия папок
alter table public.reels add column if not exists added_at    timestamptz;
create index if not exists idx_reels_collection on public.reels (collection);
alter table public.import_sessions add column if not exists collection text;
```

- Значения `collection` — человеческие названия как есть, без словаря слагов: `Нейросети`,
  `Остальное`. В URL уходят закодированными; справочник не заводим, список для выпадашки берётся
  как `distinct`.
- У 25 ссылок из 1068 папок больше одной — `source_name` хранит их через запятую, фильтр по
  `ilike`. Массив ради 2% случаев не оправдан.
- **Правило при импорте:** метка ставится только новым рилсам, у существующего не
  перезаписывается — иначе повторный импорт той же ссылки переносил бы её между группами задним
  числом.

## Реализация (готовый план исполнения — сессия модуля НЕ планирует заново)

- **Модель сессии:** `sonnet`. Объём — шесть файлов и один скрипт, архитектурные решения уже
  приняты здесь, думать заново не над чем.
- **Команда запуска:** `claude --model sonnet --permission-mode acceptEdits`.
- **Параллелить нечем и не нужно:** порядок строго последовательный, каждый шаг проверяется
  данными предыдущего. Резать шесть файлов между агентами дороже, чем сделать одной сессией.

### Этап 1. Миграция

Написать `supabase/migrations/0004_collections.sql` по SQL выше. **Сама сессия модуля миграцию НЕ
применяет** — применяет главная сессия через `apply_migration` (граница схемы чистая: только
`public.reels` и `public.import_sessions`, соседние схемы того же проекта Supabase не трогаются).
Проверка: колонки видны в `select` через supabase-клиент.

### Этап 2. Разметка того, что уже в базе

Скрипт `backend/app/workers/backfill_collections.py` по образцу `backfill_followers.py` —
идемпотентный, с аргументами `--dry-run` и `--export-dir`.

**Про путь к выгрузке.** Папка `your_instagram_activity 2/` (17 МБ) лежит только в главном рабочем
дереве и в git не хранится — в worktree модуля её физически нет. Поэтому путь задаётся аргументом
`--export-dir`, а по умолчанию берётся каталог главного дерева: `git rev-parse --git-common-dir`
даёт `<главное дерево>/.git`, от него на уровень вверх. Копировать выгрузку в worktree не нужно.

Читает из неё:

- `messages/**/neyro_set7*/**.json` — диалог целиком: ссылка берётся из `share.link`, дата из
  `timestamp_ms`, автор из `share.original_content_owner`, текст из `share.share_text`;
- `saved/saved_collections.json` — папки, в названии которых есть «нейросети» или «ИИ»;
- `saved/saved_posts.json` — лента сохранённого: дата из `timestamp`, текст из поля «Описание».

Что проставляет:

| Поле | Источник | Известно для |
|---|---|---|
| `collection` | совпадение с диалогом или папками → `Нейросети`, иначе `Остальное` | всех 704 |
| `source_kind`, `source_name` | диалог / имя папки / лента | директ 766, папки 1068 |
| `added_at` | `timestamp_ms` сообщения, `timestamp` записи ленты | 766 из директа (янв 2025 — авг 2026), 1393 из ленты |
| `caption`, **только если пусто** | `share.share_text`, «Описание» | 675 из директа, 1345 из ленты |
| `author_handle`, **только если пусто** | `share.original_content_owner` | 766 |

Непустые `caption` и `author_handle` **не перезаписывать** — данные из API свежее и точнее,
выгрузка лишь закрывает пробелы (сейчас это 8 текстов и 9 авторов из 50 и 42 пустых). Даты
добавления ссылки в папку в выгрузке нет — у папки одна общая дата, поэтому для `source_kind =
папка` поле `added_at` остаётся пустым. Метрик в выгрузке нет вообще.

**Грабли:** названия папок в `saved_collections.json` записаны с битой кодировкой (UTF-8,
прочитанный как latin-1): «Нейросети» выглядит как `ÐÐµÐ¹ÑÐ¾ÑÐµÑÐ¸`. Перед сравнением чинить через
`value.encode('latin-1').decode('utf-8')` в `try/except` — иначе фильтр по названию не найдёт ни
одной папки и всё уедет в «Остальное». Та же беда в `share_text` и в «Описании».

Ожидаемый результат: **668 / 36**.

### Этап 3. Бэкенд

- `reels.py` — параметр `collection` в `list_reels` (фильтр рядом с `author`/`min_views`),
  `added_at` в `_SORT_MAP`, новые поля в `_build_row`.
- `export_.py` — тот же параметр в `export_reels`, иначе экспорт «по заданию» отдаст всю базу.
- `sessions.py` — `collection` в ответе `list_sessions`; новый `GET /api/collections`: название,
  число рилсов, готово / без аудио / в очереди. Считать одним запросом без N+1 — образец уже есть
  в `list_sessions`.
- `schemas.py` — `collection` в `ImportRequest` и `SessionSummary`; `source_kind`, `source_name`,
  `added_at` в `ReelRow`.
- `import_service.py` — писать `collection` в `import_sessions` и в новые строки `reels` (блок
  batch insert, ~строка 75).

### Этап 4. Фронтенд

- `History.jsx` — вместо плоской таблицы карточки заданий со счётчиками; клик →
  `/results?collection=…`; внутри карточки раскрывающийся список её сессий; сессии с `total = 0`
  не рендерить.
- `Import.jsx` — поле «Задание» в форме (выбор существующего + ввод нового); блок «История
  импортов» заменить на те же карточки; кнопку «📊 Все распознавания →» оставить как есть.
- `Results.jsx` — читать `collection` из query, передавать в `getReels` и `exportUrl`, показывать
  название задания в шапке рядом с `sessionNote`. Две новые колонки в массиве `COLS` (оформление —
  как у соседних, сверяться с `reelscribe_v12.html`): **«Источник»** с тултипом на полный список
  папок и **«Добавлен»** с сортировкой через `sortKey`.
- `api/client.js` — прокинуть `collection` в `getReels`/`exportUrl`, добавить `getCollections()`.

Отдельную страницу «все разобранные» делать не нужно: `/results` без сессии уже отдаёт всю базу
(`GET /api/reels` возвращает `total: 704`), и кнопка на неё на главной есть.

## Критерии приёмки

1. `cd backend && pytest && ruff check .` — зелёные.
2. `python -m app.workers.backfill_collections` печатает **668 / 36**; повторный запуск —
   `0 изменений`.
3. `GET /api/collections` возвращает две записи с теми же числами.
4. `GET /api/reels?collection=Остальное` → `total: 36`.
5. У рилсов из директа непустые `source_name = neyro_set7` и `added_at` в диапазоне январь 2025 —
   август 2026; у рилсов из папок в `source_name` название папки. Пустых `caption`/`author_handle`
   стало на 8 и 9 меньше, **непустые не изменились** — сверить выборочно до и после.
6. В браузере на `http://localhost:5240`: история — две карточки без пустых сессий; клик по
   «Нейросети» открывает таблицу на 668 строк; колонки «Источник» и «Добавлен» заполнены и
   сортируются; экспорт из этого вида отдаёт столько же строк.
7. **Регрессия:** старые ссылки `/results/<sessionId>` и `/errors/<sessionId>` работают, счётчики
   на них не изменились; импорт без выбора задания не падает.
