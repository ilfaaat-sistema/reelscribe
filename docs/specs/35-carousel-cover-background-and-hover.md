## Облачная обработка

- Новый worker GitHub Actions вызывает только фиксированный Production API и read-only список существующих каруселей. Ни Meta/Apify-сбора, ни provider SDK, ни новых секретов. Авторизация GitHub — стандартный ephemeral github.token; генерация остаётся на Vercel с готовым OIDC.
- Инвентаризация страницами100 по archive14d/7d/14d/30d, favorites_only=false, дедуп ID. Сохранить подходящие периоды, выбирать30d→14d→archive14d→7d; 422/404 до модели позволяет проверить другой сохранённый период. Фильтры конкретного браузера не определяют серверный каталог.
- Режимы: `existing` фиксирует исходный каталог и завершается после его терминальных исходов; `continuous` также подхватывает новые существующие карточки при следующих запусках; `archive` ограничен archive14d. Пользователь выбрал continuous: все существующие и затем новые карточки. Реализовать все три режима; при разрешённой активации использовать continuous.
- Два одновременных POST, HTTP keep-alive, без транспортных/SDK повторов модели. Сначала пакетный GET кэша. ready/no_text/unreadable/image_unavailable/error уже существуют — не POST. Running только проверять GET. Busy не расходует попытку: отложить ID и сверить позже; никогда не крутить быстрые POST-повторы.
- При limit_reached сохранить pause_until из retry_after/reset_at и продолжить после московской полуночи. Пользователь отдельно разрешил завершить остаток сегодня: временно2500 попыток только23.10.2026 МСК, автоматический возврат500 после00:00. БД остаётся единственной защитой фактического дневного лимита и двух глобальных слотов, включая обычный браузер. Счётчики/ошибки/кэш не сбрасывать.
- Терминальная ошибка отдельной картинки помечается review и не повторяется. При неизвестном транспортном исходе пометить unknown, остановить новые POST, дать текущим завершиться; последующие запуски могут восстановить результат только через GET. Missing после unknown не даёт права на автоматический повтор. При401/403 или серии3 ошибок остановить запуск, сохранить причину; остальные данные не терять.

## Постоянное состояние и workflow

- Отдельная data-ветка `data/carousel-cover-background`: только state.json, marker `.carousel-cover-background-data`, vercel.json с отключённым deploy. Не использовать ветку подписи. Создание/чтение проверяет marker и отсутствие кода; CAS git-ref force=false, конфликт сохраняемой версии останавливает новые POST. Можно использовать проверенный алгоритм caption_bulk_store, но не менять его файл/контракт.
- State: schema version, mode, timestamps, inventory identity, items(ID,periods,status,first_inflight_at,safe_error_code,http_ms), counters, pause_until/reason. Никаких картинок, caption/translation, signed URL, токенов или credentials. Размер ограничить10MiB, IDs/статусы/даты валидировать.
- Перед пачкой до10 ID сохранять inflight checkpoint, затем обрабатывать максимум2 одновременно, после пачки сохранять исходы. После crash готовое восстанавливать GET; незавершённое не возвращать слепо в pending. Фиксация намерения не является доказательством отправленного запроса; сомнительные записи оставлять review/unknown до явной сверки.
- Workflow `.github/workflows/carousel-cover-background.yml`: dispatch + cron каждые15минут со сдвигом (например7,22,37,52), только main, concurrency отдельная с cancel-in-progress=false, contents:write/actions:read. Пин actions и httpx как в существующих workflows. Timeout30минут, рабочий цикл до20минут с запасом360с на завершение in-flight/checkpoint.
- Включение repository variable `CAROUSEL_COVER_BACKGROUND_ENABLED`; mode отдельная `CAROUSEL_COVER_BACKGROUND_MODE`. Disabled не отправляет POST. Смена режима не удаляет историю неизвестных/терминальных исходов. Отсутствующий enabled означает выключено.
- Журнал в Actions и checkpoint: времена HTTP, успехи/пропуски/ошибки/осталось, текущий режим/пауза. Расчёт рублей отмечать оценкой по benchmark, а не фактическим списанием; существующая БД сохраняет model usage/duration. Во время паузы не держать runner спящим до полуночи — завершать job.
- Использовать публичный репозиторий/его существующую инфраструктуру, не подключать платный тариф автоматически. Сервис обложек не получает новых endpoint/миграций; серверные счётчики уже готовы.
