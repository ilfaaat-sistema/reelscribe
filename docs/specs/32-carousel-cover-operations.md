# Эксплуатация перевода обложек каруселей

Сервис использует Vertex AI и закрытое хранилище Supabase. Секреты задаются через защищённые настройки окружения и не включаются в репозиторий, ответы API или журналы.

Перед включением:

1. Проверить доступность выбранной модели, квоты и авторизацию целевого Google Cloud project. Для Vercel используется режим vercel_oidc с проверкой issuer, audience, subject и срока действия токена. Для разрешённого локального запуска используется ADC. API-key fallback запрещён.
2. Настроить CAROUSEL_COVER_VERTEX_PROJECT, CAROUSEL_COVER_VERTEX_LOCATION, CAROUSEL_COVER_VERTEX_MODEL, CAROUSEL_COVER_AUTH_MODE, CAROUSEL_COVER_WIF_AUDIENCE и CAROUSEL_COVER_SERVICE_ACCOUNT_EMAIL. Использовать значения своего окружения: <GOOGLE_CLOUD_PROJECT>, <WIF_AUDIENCE>, <SERVICE_ACCOUNT_EMAIL>.
3. Настроить отдельный service-role доступ к Supabase через защищённое окружение. Проверить закрытые права таблиц и RPC; публичные роли не должны управлять бюджетом или обработкой.
4. Сверить локальную и удалённую историю миграций и все ожидающие файлы. Применять только согласованные миграции штатным db push. Не подменять проверку истории ручным DDL или изменением статусов миграций.
5. Проверить исходные счётчики и режим бюджета. Все реальные попытки пилота учитываются общим лимитом; переключение режима и версии не возвращает попытки.

Включение и проверка:

- CAROUSEL_COVER_TRANSLATION_ENABLED управляет новыми обработками. GET /api/radar/carousel-cover-translations читает кэш без запуска модели; POST запускает разрешённую обработку.
- Режим pilot ограничен 20 попытками всего. После успешной приёмки режим live включается через закрытую RPC бюджета: 500 попыток за календарные сутки Europe/Moscow с учётом попыток пилота того же дня.
- Проверить два глобальных слота, дедупликацию, отсутствие платных повторов, ready/no_text и безопасные терминальные статусы. Таймаут с неизвестным исходом требует ручной сверки; слот нельзя освобождать для слепого повтора.
- Проверить карточку и полную панель на широком экране и мобильной ширине, сохранность фильтров и отбора. При daily-limit retry_after должен указывать следующую московскую полночь; клиент повторно начинает с GET только при видимости.

Откат: выключить новые обработки флагом, сохранив кэш, счётчики и результаты. Не удалять записи бюджета и не сбрасывать lifetime-счётчик. Runtime-ошибки диагностировать по безопасным метаданным без токенов, signed URL и ответов провайдера с чувствительными данными.
