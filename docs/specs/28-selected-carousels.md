# Отбор отдельных каруселей: ТЗ и поэтапный план

Дата: 20.10.2026. Статус: проект на утверждение, код не реализуется.

## 1. Решения пользователя и цель

Пользователь хочет отмечать конкретные карусели на `/radar/carousels?period=14d` и открывать все отмеченные в отдельном разделе для последующей адаптации в свой стиль. Ответ «тут карусели показываются хочу сами карусели лайкать и отбирать» трактуется как внутренняя отметка ReelScribe. Отправка настоящего лайка в Instagram в это ТЗ не входит. Пользователь явно выбрал **хранение на сервере, вход и доступ с разных устройств**.

Три независимых действия: звезда — избранный автор; перечёркнутый глаз — скрытый автор; новая закладка «Отобрать» — одна публикация. Внешний счётчик `likes` не меняется от внутреннего отбора. Значок закладки выбран, чтобы не смешивать отбор с сердцем у статистики Instagram.

Результат выпуска: личная сохраняемая подборка, доступная после входа на другом устройстве; возможность открыть оригинал и сохранённый текст. Генерация и автоматическая адаптация — следующий выпуск.

Таблицы личного отбора среди локальных миграций нет. Живая схема и настройки Auth не проверялись; совпадение с локальными файлами не предполагается.

Периоды 7/14 дней сейчас означают фиксированные наборы 13–19 и 6–19 октября 2026, а не скользящее окно. Полноту текущего облачного сбора этот документ не подтверждает.

Опубликованный URL недоступен инструменту веб-чтения; визуальная проверка сайта в этом ходе не выполнена. Выводы о поведении основаны на локальном коде. Секреты не читались, Meta-сбор не запускался, БД не изменялась. В репозитории есть чужие незакоммиченные документы; их не включать в реализацию.

## 3. Пользовательский путь

1. Общая сетка остаётся доступна без входа. На карточке появляется отдельная кнопка с закладкой, названием «Отобрать карусель» и `aria-pressed`. Нажатие не открывает drawer и не переключает звезду/глаз.
2. Если входа нет, открывается вход с возвратом к тому же URL, фильтрам, позиции и выбранной публикации. Проектное решение на утверждение: вход по одноразовому коду на email через Supabase Auth. После успешного входа первоначальный отбор завершается один раз. Отмена входа ничего не сохраняет. Способ входа и готовность доставки писем проверяются до реализации.
3. Во время записи кнопка показывает ожидание; повторные клики блокируются. После подтверждения сервера — «Отобрано» и обновлённый счётчик. При ошибке сохраняется прежнее подтверждённое состояние, появляется понятная ошибка и повтор.
4. Та же кнопка есть в просмотре. Повторное нажатие снимает отметку. После снятия доступна «Отменить»; отмена — новая серверная операция, а не только визуальный возврат.
5. Из заголовка каруселей доступен раздел «Отобранные карусели (N)», новый маршрут `/radar/carousels/selected`. N — число всех записей текущего пользователя, включая отсутствующие в свежем отчёте. До загрузки показывается ожидание, а не ложный ноль.
6. В разделе — сетка, поиск по автору и сохранённому тексту, сортировки по дате отбора (по умолчанию новые сначала), публикации, лайкам и комментариям; направление asc/desc. Для метрик отображается дата снимка. Неизвестные значения всегда в конце, при равенстве — стабильный порядок по ID. Подгрузка по 50/100; отдельно «показано / найдено» и общее N.
7. Подборка охватывает все периоды. Фильтры общей сетки, включая избранных, скрытых авторов и NEYRO_SET7, не исключают из неё записи. У скрытого автора отображается пояснение; его отобранная карусель открывается. Скрытие автора не снимает отбор. Старое поведение скрытия в общей сетке сохраняется.
8. Drawer показывает сохранённый текст, автора, дату, метрики и Instagram embed для просмотра доступных слайдов. Есть ссылка «Открыть в Instagram». Нового собственного слайдера нет: текущий API не содержит массива слайдов, а caption не является текстом со слайдов.
9. Снятая отметка убирает карточку из результатов, но не закрывает неожиданно уже открытый drawer; в нём остаются оригинал и кнопка повторного отбора. Счётчики пересчитываются. Пустая подборка и отсутствие совпадений поиска — разные состояния.
10. «Все карусели» и browser Back возвращают параметры и прокрутку общей сетки; закрытие drawer сохраняет поиск/сортировку/позицию подборки. Прямой вход без истории возвращает на `/radar/carousels?period=14d`. `returnTo` разрешает только внутренние маршруты каруселей, без внешних URL.
11. Выход очищает пользовательское состояние и кэш в памяти. Записи предыдущего пользователя не видны следующему, включая краткое появление при загрузке. Для чтения подборки также требуется вход.

## 4. Сохранность данных и границы

Отбор хранит ID **и серверный снимок** разрешённых данных. Исчезновение из отчёта, смена периода, обновление страницы, повторный сбор и изменение username не удаляют отметку. Отметка привязана к Instagram ID, не к автору, позиции, shortcode или периоду.

Снимок хранит текст и метаданные, но не архив изображений. CDN-ссылки могут устареть; embed может стать недоступен. Тогда остаются сохранённый текст, сведения, ссылка и заглушка обложки. Нельзя обещать вечное хранение всех слайдов. Самостоятельное скачивание, OCR, перевод и восстановление удалённого оригинала в этот выпуск не входят.

Отсутствие в успешно прочитанном актуальном отчёте обозначается «Нет в текущем отчёте; показана сохранённая копия». Ошибка 503/сети означает «Не удалось проверить актуальность», а не удаление из Instagram. Проверка доступности отчёта не блокирует список подборки; не выполнять отдельный запрос на каждый элемент. Снимок при отборе неизменяем в пределах этой отметки; обновление метрик/снимка автоматически не требуется. При снятии и повторном отборе создаётся новый снимок.

Если пользователь нажал отбор на карточке, уже исчезнувшей из обоих доступных отчётов, и сервер ещё не имеет его снимка, вернуть явную ошибку, не показывать успех. Для «Отменить снятие» сервер сохраняет снимок снятой записи; это позволяет восстановить отбор даже после исчезновения оригинала из отчёта.

## 5. Хранение и безопасность

| Вариант | Возможности и цена объёма | Решение |
|---|---|---|
| localStorage | Без входа и миграций, только этот браузер/домен; очистка данных сайта теряет подборку, нет синхронизации | Отклонён пользователем |
| Сервер + пользовательский вход | Общая подборка между устройствами; нужны Auth, API, таблица, политики доступа и миграция | Выбран |

Новая таблица (предлагаемое имя) `public.carousel_selections`:

- `user_id uuid` — владелец из проверенной сервером сессии;
- `instagram_media_id text` — строка цифр 1–40 символов; составной первичный ключ `(user_id, instagram_media_id)`;
- `selected_at`, `updated_at`, `removed_at` — серверное время; `removed_at = null` означает активный отбор;
- `snapshot_version = 1`, `snapshot jsonb` — только whitelist полей текущего `ITEM_KEYS` API: id, username, permalink, shortcode, timestamp, caption, media_type, media_url, thumbnail_url, likes, comments, views, followers, collected_at;
- `source_period`, `source_start_date`, `source_end_date`, `snapshot_at` — происхождение снимка;
- `revision` — версия изменения для защиты от устаревшей записи.

Не добавлять FK на UUID `reels.id` или на отчёт. Снятие — логическое (`removed_at`); снятые записи исключаются из списка и счётчика. Это обеспечивает отмену и разрешение конфликтов. Политику окончательной очистки снятых записей вынести в последующий выпуск; пользователю не обещать физическое удаление при снятии отметки. При удалении учётной записи удаляются её записи отбора.

Сервер принимает ID и период, но не произвольный snapshot/URL от клиента; получает данные из уже существующего источника отчётов. Повторное PUT для активной записи не меняет `selected_at` и не создаёт дубль. Индекс по владельцу, активности, дате отбора; остальные индексы — по измерениям плана запроса на согласованном объёме.

Все новые API требуют проверенной сессии; `user_id` не принимается из тела или query. RLS разрешает владельцу только свои строки, с проверкой владельца при записи. Публичные старые политики не копировать. Права ролей и RLS проверять отдельно. Серверные привилегированные ключи не передавать браузеру; защищённые запросы выполнять в контексте пользователя. Основание: [официальная документация Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

Новая защита относится к подборке; это не объявление всего существующего приложения многопользовательским. Старые звёзды и скрытые авторы остаются локальными и не мигрируют автоматически. Новые личные ответы не попадают в публичный кэш (`Cache-Control: private, no-store`). Снимок ограничить 64 КиБ с явной ошибкой превышения, без молчаливого обрезания caption. Текст выводить как текст; URL проверять теми же ограничениями HTTPS/Instagram, что в существующем API.

Миграция требуется только для новой таблицы, индексов, RLS и grants. Перед применением проверить фактический проект, схему и **все** ожидающие миграции. Создать миграцию штатным CLI, применять через `db push` после предусмотренной проверки; не использовать MCP apply_migration или repair для обхода рассинхронизации. В этом ходе миграции не создаются и не применяются. До реализации также проверить настройку Auth, callback URL, доставку email и доступные лимиты; их работоспособность пока не подтверждена. Changelog Supabase не прочитан веб-инструментом из-за неподдерживаемого content-type; перед реализацией проверить его доступным способом.

## 6. Предлагаемые контракты API и синхронизации

Все маршруты ниже новые, под `/api/radar/carousel-selections`, отдельно от read-only `/api/radar/carousels`.

| Метод/маршрут | Контракт |
|---|---|
| GET `/` | `q` до 200 символов, `sort=selected_at|timestamp|likes|comments`, `order`, `limit=50|100`, `offset>=0`; ответ `{items,total,selected_total}`; поиск регистронезависимый по username без @ и caption |
| POST `/status` | `{ids:[...]}` до 100 ID видимой порции; `{states:[{id,selected,revision}],selected_total}`; неизвестные ID имеют `selected:false, revision:0` |
| GET `/{id}` | Сохранённая активная запись владельца, включая snapshot; чужая/отсутствующая — одинаковый 404 |
| PUT `/{id}` | `{source_period:'7d'|'14d',expected_revision}`; идемпотентный отбор или восстановление; `{item,selected_total}` |
| DELETE `/{id}` | `expected_revision` в query; логическое снятие; `{id,selected:false,revision,selected_total}` |

Элемент: `{id, selected, selected_at, revision, snapshot, source_period, source_start_date, source_end_date, snapshot_at}`. Статические маршруты зарегистрировать раньше `/{id}`. Ошибки: 401 — вход истёк; 404 — нет доступного источника/записи; 409 — конфликт версии; 422 — некорректный ввод/превышение размера; 503 — временно недоступен источник или хранилище. Ошибки не раскрывают чужие записи.

Обновление версии и счётчика выполняется согласованно в транзакции. Повтор уже достигнутого состояния возвращает успех без новой записи; противоположная операция с устаревшей версией — 409 и актуальное состояние, без слепой перезаписи. Клиент обновляет состояние и предлагает повторить намерение. Снятие отсутствующего ID идемпотентно.

При открытии страницы, возврате фокуса и после изменения запрашивается актуальное состояние. В активной вкладке — проверка раз в 30 секунд без перекрывающихся запросов; скрытая вкладка не опрашивает. Цель синхронизации между устройствами: при фокусе сразу после ответа API, в открытой активной вкладке — в пределах одного интервала плюс время запроса. WebSocket/Realtime для первого выпуска не нужен. При отсутствии сети подборка не объявляется пустой; изменения не считаются сохранёнными, скрытой очереди offline-записей нет.

## 7. Связь с адаптацией и «Контент заводом»

В этом выпуске сохраняется исходный материал для будущей команды «Адаптировать в моём стиле». Рабочую кнопку генерации пока не показывать. Будущий контракт передачи: ID источника, permalink, snapshot/version, выбранный профиль стиля, отдельный ID задания; разрешение на передачу и бюджет — в следующем ТЗ.

Существующий план упоминает bright/«Яркая». Этот выпуск не выбирает за пользователя конкретные параметры стиля. Для полноценной адаптации понадобятся все слайды, их текст и визуальный смысл; текущий snapshot этого не содержит. Следующий этап должен получить оригинал, проверить полноту, затем запускать адаптацию. Отбор сам по себе не запускает сбор, платные API, OCR или генерацию и не изменяет проект «Контент завода».

Две младшие модели не меняют одни файлы. При недостаточном качестве ограниченной задачи — передать старшей, без повторяющихся слабых попыток. Не назначать отдельного агента на простую механическую сверку. В текущем ходе агенты не запускаются: подготовка одного ТЗ не оправдывает накладных расходов.

## 9. Проверки и критерии готовности

- Две карусели одного автора: отмечена только одна; звезда автора и глаз неизменны. Снятие в drawer синхронно отражается на карточке/счётчике.
- Отметить в 14d, открыть 7d, обновить отчёт и перезагрузить: запись остаётся. Один ID в обоих периодах не дублируется. Тест удаления источника из отчёта сохраняет snapshot и работающее снятие/отмену.
- Два разных пользователя не читают/меняют записи друг друга через список, status, детали, прямой REST БД и подстановку ID. Без входа запись запрещена. Проверить просроченный/поддельный токен и выход во время запроса; запоздавший ответ не возвращает данные старого пользователя.
- Один пользователь на двух устройствах: запись появляется в установленный срок; конфликт одновременного отбора/снятия не теряет более новое подтверждённое действие. Повтор сетевого запроса не создаёт дубль.
- Snapshot хранит caption без HTML-исполнения; опасные URL, превышение размера и посторонние поля отклоняются. 404 отчёта, 503, недоступный embed и устаревшая обложка имеют разные корректные fallback-состояния.
- Поиск, сортировки с null, равными значениями и пагинация проверены на фиксированном наборе; пустой результат не обнуляет общий счётчик. Снятие последней карточки страницы корректно корректирует выдачу.
- Старые сценарии: 7d/14d и автоматический период; поиск автора/транслитерация; избранные и скрытые авторы с прежними localStorage-ключами; NEYRO_SET7; сортировки; подгрузка 50/100; обновление отчёта; ссылки с id; возврат в каталог и восстановление скролла. Парсер, просмотр Reels, заметки, перевод и навигация не сломаны.
- Запустить существующие тесты `frontend/src/api/*.test.js` через node:test, backend pytest для carousels и новых модулей, новые тесты Auth/RLS; `npm run lint` и `npm run build` в frontend. Не заявлять npm test — такого скрипта сейчас нет. Команды backend уточнить по установленному окружению, не менять версии ради запуска.

Проверить обычную/отмеченную карточку, вход, подборку, drawer, пустое состояние и ошибку; счётчики по DOM, внешний вид по скриншотам. Сохранить существующий состав блоков и сетку.
