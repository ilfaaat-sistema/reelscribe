# Перевод текста публикации карусели

Статус: реализация в отдельном worktree выполнена, локальные тесты и review пройдены, 20.10.2026. Пользователь разрешил завершить без визуальной проверки; миграция, серверный ключ, merge и публикация не выполнены. Текущее состояние — в `31-carousel-caption-translation-state.md`.

## Задача и проверенное состояние

В окне карусели нужен русский перевод подписи автора с возможностью вернуться к оригиналу, как в `/results`.
`frontend/src/pages/Carousels.jsx` сейчас выводит только `item.caption`.
`frontend/src/components/ReelDrawer.jsx` использует `api/translation.js` и сохраняемый перевод рилса.
`backend/app/api/translation.py` принимает UUID записи `reels`; ID каруселей и источники их деталей другие.
Готовый переводчик и проверки качества находятся в `backend/app/pipeline/translate.py`.
Следовательно, одного добавления кнопки недостаточно: нужен серверный маршрут для сохранённой карусели и постоянный кэш.

## Поведение

- При иностранной подписи без перевода показать кнопку «Перевести» рядом с «Текст публикации».
- Перевод запускать по нажатию; состояние «Переводим…» исключает повторный запрос.
- После успеха показывать русский текст и переключатель «Оригинал / Русский» по образцу окна рилса.
- Сохранять результат между открытиями и устройствами; повторное чтение готового перевода не вызывает переводчик.
- Привязать кэш к ID публикации и отпечатку исходного текста: изменение подписи исключает устаревший перевод.
- Для русской, пустой и не требующей перевода подписи применять существующие правила.
- При ошибке сохранить оригинал, показать понятную ошибку и возможность повторить запрос.
- Переводится подпись справа на пользовательском скриншоте. Перевод текста внутри изображений потребовал бы отдельного распознавания и отдельного согласования.

## Контракт

Отдельный POST для перевода подписи карусели принимает ID и контекст периода; сервер получает исходник из уже сохранённых данных, без повторного сбора Instagram. Произвольный текст клиента не принимается как источник для перевода.
Ответ содержит перевод, язык при наличии и идентификатор версии исходника. Чтение деталей предоставляет соответствующий сохранённый перевод.
Используются существующий переводчик, проверка результата и ограничения расхода; автоматический массовый перевод не запускается.
Постоянное хранение и конкурентные запросы требуют проверки действующей схемы и полномочий перед подготовкой миграции. Миграция и выкат согласуются отдельно после готовности проверяемого изменения.

## Порядок работ и исполнители

Указание пользователя для этой задачи: Astra участвует только в самых ключевых решениях; основную работу выполняют GPT-6.1 и GPT-5.6. Доступные идентификаторы: `gpt-6-astra`, `gpt-6.1-sol`, `gpt-5.6-sol`. Это распределение ответственности, без неподтверждённых утверждений о цене или скорости моделей.

### Подготовка и фиксация контракта

GPT-6.1 проверяет актуальную ветку, чужие изменения, действующую схему, способы открытия каруселей и исходный вид окна. Создаёт отдельные ветку и worktree для фичи. Подготавливает точный контракт: URL и тело POST, поля ответа и деталей, коды ошибок, поведение при изменении подписи, хранение и конкурентное выполнение. Изучает необходимые навыки перед работой с БД.

Astra проверяет только ключевые решения по постоянному кэшу, защите публичного платного endpoint и совместимости с существующим переводом. На вход получает краткий контракт и найденные ограничения со ссылками на код. До этой проверки не запускаются независимые реализации с разными предположениями об API. Существенное изменение объёма выносится пользователю.

### Параллельная реализация после фиксации контракта

| Исполнитель | Объём и исключительное владение | Зависимости и результат |
|---|---|---|
| GPT-6.1, сервер | Новый сервис и маршрут перевода карусели, подключение маршрута, серверное чтение кэша, необходимые новые миграции, серверные тесты | Зафиксированный контракт и решение по хранилищу; переводчик переиспользуется, проверяются кэш, изменённый исходник, ошибки и ограничения |
| GPT-5.6, интерфейс | `frontend/src/api/carousels.js`, `frontend/src/pages/Carousels.jsx`, `frontend/src/pages/carousels.css`, относящиеся к ним клиентские тесты | Тот же контракт; работает с подменёнными ответами API до готовности сервера, реализует переключатель, ожидание, ошибку, защиту от устаревшего ответа |

Оба исполнителя работают в worktree фичи, каждый меняет только свои файлы. Общие изменения API-контракта согласуются через корень до правок; при необходимости изменения существующего общего переводчика его владельцем остаётся серверный исполнитель. Новые CSS-классы имеют префикс `carousels-translation-`; существующие стили рилсов не переписываются. Агент интерфейса не меняет схему или сервер ради удобства моков.

Одновременно работают максимум два исполнителя плюс корень. Третьего исполнителя на проверки не запускать до появления собранного результата: это создаст лишние повторы. Передача задач — через короткое ТЗ и адресные файлы, без полной истории и секретов. При недостаточном качестве ограниченной реализации задача передаётся GPT-6.1; серия слабых повторных попыток не проводится.

### Интеграция и приёмка

После завершения обоих исполнителей GPT-6.1 сверяет контракт и интегрирует сервер с интерфейсом, устраняет несовместимости. Затем GPT-5.6 выполняет ограниченную независимую проверку по списку приёмки: серверные тесты, клиентские тесты, сборку, линтер, старые сценарии перевода и браузерную проверку. Не изменяет реализацию одновременно с её владельцем; найденные ошибки передаёт с воспроизводимым примером. Механические сверки выполняются кодом.

Astra проводит итоговую приёмку по диффу и сохранённым результатам проверок: расход, конкурентные запросы, сохранность исходного текста и данных, регрессии, итоговый скриншот. Рутинные тесты и поиск файлов повторно ей не поручаются. Корень сохраняет статус и представляет конкретные изменения хранения и выката для разрешения; после разрешённой публикации GPT-6.1 проверяет основной сайт.

Таким образом, параллельная часть — сервер и интерфейс; последовательно выполняются фиксация контракта → интеграция → приёмка → разрешённый выкат. Ни миграция, ни публикация не считаются разрешёнными одним согласованием состава исполнителей.

## Приёмка

- Иностранная подпись переводится; оригинал доступен без повторного запроса.
- Повторное открытие использует сохранённый перевод; изменённый исходник не получает старый перевод.
- Проверены отсутствие исходника, сбой переводчика, лимит и повторные конкурентные нажатия.
- Закрытие окна или переход к другой карточке во время запроса не подменяет текст новой карточки.
- Проверены живые периоды 14/30 дней и архивные 7d/archive14d, а также открытие из отбора, если оно использует это окно.
- Существующий перевод подписи и расшифровки в `/results` продолжает работать.
- Данные карточки, просмотр слайдов, отбор и фильтры сохраняются; переключатель не ломает узкое окно.
- Фактические проверки и оставшиеся ограничения записаны в документ состояния перед сдачей.
