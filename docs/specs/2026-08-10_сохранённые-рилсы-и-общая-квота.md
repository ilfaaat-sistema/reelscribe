Составлено 2026-08-10 по итогам переезда инфраструктуры на Vercel + GitHub Actions.

## Задача A. Общий cooldown API-ключей между воркерами

### Проблема

Cooldown ключей после HTTP 429 живёт **в памяти процесса**: `_cooldown` в
`backend/app/pipeline/starapi_downloader.py` и `_cooldown` / `_actor_cooldown` в
`backend/app/pipeline/apify_client.py`.

Пока воркер был один, это работало. Теперь воркеров может быть два одновременно — на GitHub
Actions и локальный на Mac. Двойной обработки задания не будет (claim атомарный,
`backend/app/workers/run.py`), но каждый процесс видит свою картину квот: оба независимо
упираются в 429 по одному и тому же ключу и продлевают простой вместо того, чтобы переждать его
один раз. Сейчас это закрыто только предупреждением в `README.md` — «не запускать параллельно»,
что неудобно и легко нарушить случайно.

### Что сделать

Перенести состояние cooldown в Supabase, чтобы воркеры его разделяли.

- Миграция `supabase/migrations/0003_key_cooldown.sql`: таблица вида
  `key_cooldown(provider text, key_ref text, actor text null, until timestamptz, primary key (provider, key_ref, actor))`.
- **Секреты в базу не писать.** `key_ref` — не сам ключ, а его идентификатор: хеш (sha256, первые
  16 символов) либо последние 6 знаков, как уже делают логи (`token[-6:]` в `apify_client.py`).
- Чтение и запись обернуть так, чтобы недоступность базы не роняла скачивание: при ошибке —
  падать обратно на текущее поведение в памяти (best-effort, как сделано в
  `_check_rate_limit` в `backend/app/api/import_.py`).
- Разделение «cooldown аккаунта» и «cooldown пары (токен, actor)» из `apify_client.py` сохранить —
  оно появилось не просто так: 402 и `platform-feature-disabled` относятся к конкретному актору,
  и глобальный бан токена убивал бы основной каскад загрузки.
- После этого снять предупреждение из `README.md` и `CLAUDE.md`.

### Проверка

Запустить локальный воркер и `workflow_dispatch` на Actions одновременно на непустой очереди;
убедиться, что после 429 у одного второй не долбит тот же ключ (видно по логам обоих).

## Задача B. Импорт сохранённых рилсов и рилсов из переписки

### Что есть у пользователя

Папка `your_instagram_activity 2/` в корне проекта (в `.gitignore`, в репозиторий не попадает):

| Файл | Размер | Что внутри |
|---|---|---|
| `saved/saved_posts.json` | **7,1 МБ** | **1393 записи** сохранённых постов/рилсов |
| `messages/inbox/<тред>/message_1.json` | суммарно 47 МБ | переписки, в т.ч. рилсы, отправленные на профиль «нейросет7» |

**Формат `saved_posts.json`** — это **список** (не объект, как `message_1.json`), запись:

```json
{
  "timestamp": 1785998113,
  "media": [],
  "fbid": "...",
  "label_values": [
    {"label": "URL", "value": "https://www.instagram.com/reel/<shortcode>/", "href": "…"},
    {"label": "Описание", "value": "…"}
  ]
}
```

Присутствует классический mojibake выгрузок Instagram (`Описание` приходит как
`ÐÐ¿Ð¸ÑÐ°Ð½Ð¸Ðµ`) — latin1→utf8. В проекте это уже умеет `parse_message_json`
(`backend/app/pipeline/normalize.py`), приём надо переиспользовать, а не писать заново.

### Три блокера, замеренных на месте

1. **Размер запроса.** `frontend/src/pages/Import.jsx` читает файл через `FileReader` и отправляет
   его содержимое целиком в поле `links_text` (строка 122), а `client.js` шлёт это как JSON-тело.
   У Vercel Hobby **жёсткий лимит 4,5 МБ на тело запроса** — файл на 7,1 МБ вернёт 413.
2. **Кап импорта.** `IMPORT_MAX_LINKS = 1000` (`backend/app/core/config.py`), а сохранённых рилсов
   **1393**.
3. **Формат.** `parse_message_json` написан под структуру переписки; список `saved_posts.json` с
   `label_values` он не разберёт.

### Что сделать

**B1. Извлекать ссылки в браузере, а не слать файл целиком.**
В `Import.jsx` после чтения файла прогнать текст регуляркой на `instagram.com/(reel|p|tv)/<shortcode>`
и отправлять на сервер только найденные ссылки. Это уменьшает тело запроса примерно в сто раз и
снимает лимит 4,5 МБ насовсем, а не поднимает его. Прецедент в коде уже есть — xlsx фронт тоже
разбирает у себя.
Серверный разбор `parse_message_json` **не удалять**: он нужен для сценария «загрузить файл через
API» и покрыт тестами.

**B2. Поддержать формат `saved_posts.json`.**
Добавить в `normalize.py` разбор списка с `label_values` (брать `label == "URL"`, плюс `timestamp`
как дату сохранения). Переиспользовать существующее лечение mojibake. Покрыть тестом на урезанном
фрагменте реального файла — **без личных данных в репозитории**, только пара анонимизированных
записей.

**B3. Рилсы, отправленные на профиль «нейросет7».**
Треды в `messages/inbox/` названы хешами и никами, папки с очевидным именем нет — нужный тред
ищется по названию внутри `message_1.json`. Сделать это разовым скриптом
(`backend/app/workers/` рядом с `backfill_followers.py`), который проходит по инбоксу, находит тред
по подстроке в участниках/названии и выкладывает список ссылок в файл. Результат скрипта **сразу
писать на диск**, а не печатать в терминал.

**B4. Кап 1000 против 1393.**
Не поднимать молча — это защита кошелька. Варианты на выбор пользователя: разбить на две партии
(проще всего, ничего менять не надо) либо поднять `IMPORT_MAX_LINKS` осознанным решением с
пониманием, во сколько обойдётся разбор 1393 рилсов на платных API.

**B5. Что именно «проанализировать» — вопрос к пользователю.**
В сервисе уже есть метрики (`er`, `lpf`, `cpf`, `eng`), сортировки, фильтры, режим чтения и
экспорт. Прежде чем что-то строить, надо выяснить, чего из этого не хватает: например, сравнение
двух наборов между собой (сохранённое против отправленного), группировка по авторам, поиск
повторяющихся тем в расшифровках. **Это уточняется до начала работ, а не додумывается.**

### Порядок

B1 → B2 → тестовый импорт маленькой партией (20–30 ссылок) → убедиться, что рилсы доходят до
`done` → только потом полный прогон. Отдельно держать в голове, что 18 из 24 прошлых падений были
«Исчерпана квота API-ключей»: перед большим прогоном стоит проверить остаток квот Apify/RapidAPI.

### Порядок задач между собой

Задачу A желательно сделать **до** большого прогона: именно на нём два воркера и подерутся за
ключи, если пользователь случайно оставит локальный запущенным.
