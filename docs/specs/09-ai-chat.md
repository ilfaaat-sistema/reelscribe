# ТЗ 09. ИИ-чат по всей базе («облачко» справа)

**Статус:** в работе

## Проблема / цель

В базе 2868 рилсов с расшифровками, подписями, саммари и тегами, плюс рилсы Радара. Найти что-то
по смыслу («кто рассказывал про очки с Гермесом», «топ рилсов про агентов за август по
залётности») сейчас можно только руками или скриптом сессии Claude. Нужен чат прямо в сервисе.

## Пользовательский сценарий

1. На любой странице (`/`, `/history`, `/results`, `/errors`, `/radar`) справа внизу видна круглая
   кнопка-облачко.
2. Клик — справа выезжает панель чата (ширина 420px, на телефоне — во всю ширину).
3. Пишу вопрос обычным языком, Enter — отправка (Shift+Enter — перенос строки).
4. Пока модель думает — индикатор «Ищу в базе…». Приходит ответ: текст + карточки найденных
   рилсов (автор, просмотры, залётность, фрагмент текста).
5. Клик по карточке — открывается обычная карточка рилса `ReelDrawer` (для рилсов парсера) или
   ссылка на Instagram в новой вкладке (для рилсов Радара).
6. История разговора переживает перезагрузку (localStorage), кнопка «Очистить» её стирает.
   В следующие вопросы уходят последние 10 реплик — можно уточнять («а у кого из них больше
   просмотров?»).

## Функциональные требования

### Контракт API (фиксирован — оба агента делают ровно так)

`POST /api/chat`

Запрос:
```json
{ "message": "кто рассказывал про очки с Гермесом",
  "history": [ {"role": "user", "text": "..."}, {"role": "assistant", "text": "..."} ] }
```
- `message` — 1…2000 символов, иначе 422.
- `history` — не больше 10 последних элементов (лишнее сервер отрезает сам), роли `user|assistant`.

Ответ 200:
```json
{ "answer": "Про очки Ray-Ban с агентом Гермес рассказывал @yanosh_iii …",
  "reels": [
    { "id": 123, "source": "parser", "shortcode": "DaFYHA0PqTN",
      "url": "https://www.instagram.com/reel/DaFYHA0PqTN/", "author": "yanosh_iii",
      "views": 348510, "er": 12.4, "posted_at": "2026-06-27",
      "snippet": "Сегодня тестировал Ray-Ban с Гермесом в гараже…" } ],
  "usage": { "steps": 3, "input_tokens": 5400, "output_tokens": 420, "thinking_tokens": 0, "cost_rub": 0.21 } }
```
- `source`: `parser` (таблица `reels`, `id` = `reels.id`, открывается `ReelDrawer`) или `radar`
  (таблица `radar_reels`, `id` = `radar_reels.id`, открывается `url`).
- `er`, `views`, `posted_at`, `snippet` могут быть `null`.
- `reels` — только те рилсы, на которые модель сослалась в ответе (не весь результат поиска),
  не больше 12, в порядке упоминания.
- `answer` — простой текст с переносами строк и `**жирным**`; фронт рендерит только `**…**` и
  переносы, остальное как есть (без markdown-библиотек).

Ошибки: 429 `{detail}` — превышен лимит; 502 `{detail}` — модель недоступна (текст ошибки Gemini
в `detail` на русском с первой строкой оригинала); 422 — плохой запрос.

### Бэкенд (агент с инструментами)

- Модель: `gemini-2.5-flash` через `google-genai`, ключ `GEMINI_API_KEY` (так же, как
  `app/radar/gemini.py`), переопределяется env `CHAT_GEMINI_MODEL`. `thinking_budget` = 512 —
  в соседнем проекте мысли модели стоили впятеро дороже ответа.
- Function calling вручную (не automatic): цикл до **6 шагов**, затем модель обязана ответить
  тем, что есть. Каждый инструмент возвращает компактный JSON (фрагменты ≤ 300 символов, не
  полные расшифровки — кроме `get_reel`).
- Инструменты:
  1. `search_text(pattern, fields?, limit=20)` — регулярное выражение POSIX без учёта регистра по
     полям: `reels.caption`, `reels.caption_ru`, `transcripts.text`, `transcripts.text_ru`,
     `transcripts.summary`, `transcripts.ocr_text`, `radar_reels.caption`. Поиск на стороне
     Postgres через PostgREST-фильтр `imatch` (не выкачивать все строки в Python). Возвращает
     `source,id,shortcode,url,author,views,er,posted_at,field,snippet` (snippet — ±120 символов
     вокруг первого совпадения). Системный промпт требует от модели сразу расширять запрос
     вариантами написания и языками: `herm[eè]s|гермес|эрмес|хермес`.
  2. `filter_reels(author?, date_from?, date_to?, min_views?, min_er?, sort_by=views|er|posted_at|likes, limit=20)` — по `reels`.
  3. `get_reel(shortcode)` — карточка + полная расшифровка (`text_ru` если есть, иначе `text`),
     обрезка до 6000 символов.
  4. `stats(group_by=author|month, top=15, date_from?, date_to?)` — число рилсов, сумма и медиана
     просмотров, средняя залётность по группе. Считать в Python по выборке метрик (2868 строк —
     допустимо, пагинация `.range()` по 1000, серверный потолок PostgREST).
- Системный промпт: русский язык ответа; отвечать только по данным инструментов, не выдумывать;
  каждое утверждение о рилсе сопровождать `@автор` и shortcode; метрики — формулы из корневого
  `CLAUDE.md` (залётность = просмотры ÷ подписчики).
- Сбор `reels` для ответа: все рилсы, которые возвращали инструменты за разговор, фильтруются по
  тому, чей `shortcode` или `@author` встречается в тексте ответа.
- `usage.cost_rub`: по тарифу flash $0.30 / 1M вход, $2.50 / 1M выход (+мысли), курс 80 ₽/$.
- Защита кошелька: rate-limit через существующую таблицу `rate_limits`, но с ключом
  `ip = 'chat:' + <ip>` (чтобы не есть лимит импорта), **30 вопросов за 10 минут** на IP. Та же
  логика, что `_check_rate_limit` в `app/api/import_.py` — вынести нельзя без правки импорта,
  поэтому своя копия в `app/api/chat.py`.
- Логирование: на каждый вопрос одна строка лога — шаги, вызванные инструменты, токены, ₽.

### Фронт

- Компонент `ChatBubble` монтируется **один раз** в `App.jsx` рядом с `<Routes>` — видим на всех
  страницах. `ReelDrawer` для карточек чата монтируется внутри `ChatBubble` (своё состояние).
- API-функция `sendChat(body)` в `frontend/src/api/client.js` рядом с остальными (через общий `req`).
- Классы CSS (фиксированы): `.chat-fab` (кнопка), `.chat-fab.is-open`, `.chat-panel`,
  `.chat-panel.is-open`, `.chat-head`, `.chat-log`, `.chat-msg`, `.chat-msg.user`,
  `.chat-msg.assistant`, `.chat-msg.error`, `.chat-cards`, `.chat-card`, `.chat-input`,
  `.chat-send`, `.chat-typing`, `.chat-cost`.
- Разметка карточки: `<button class="chat-card">` → `<span class="chat-card-author">@автор</span>`
  `<span class="chat-card-meta">348 тыс · 12.4×</span>` `<span class="chat-card-snippet">…</span>`.
  Цвет залётности — существующий `erClass` из `lib/utils.js`, формат просмотров — `fmtV`.
- Стоимость ответа мелко под сообщением: `.chat-cost` «0,21 ₽ · 3 шага».
- Стили в `frontend/src/components/chat.css`, только переменные из `:root` в `index.css`
  (`--panel`, `--line`, `--iris` и т.д.). Кнопка-облачко — inline SVG «облачко чата», 52×52,
  `position: fixed; right: 20px; bottom: 20px`, учесть `--apps-bar-h`, если панель «Мои сервисы»
  снизу (см. CLAUDE.md). Панель — `position: fixed; top:0; right:0; height: 100vh`, `z-index`
  ниже, чем у `ReelDrawer`: drawer, открытый из чата, должен лечь поверх панели.
- Esc закрывает панель (если не открыт drawer).

## Реализация (готовый план исполнения)

- **Модель сессии:** Opus оркестрирует (эта сессия), код пишут два Sonnet-субагента параллельно.
- **Агент A (sonnet), только файлы бэкенда** из списка выше. pytest на инструменты против живой
  базы (read-only), Gemini в тестах мокать. Не трогать `frontend/`.
- **Агент B (sonnet), только файлы фронта** из списка выше. `npm run build` должен проходить.
  Для отладки без бэкенда — мок ответа по контракту. Не трогать `backend/`.
- Интеграция и приёмка — Opus после отчёта обоих.

## Критерии приёмки

1. pytest: `search_text("herm[eè]s|гермес")` находит `DaFYHA0PqTN` (@yanosh_iii).
2. Живой вопрос «кто рассказывал про очки с Гермесом» → ответ называет @yanosh_iii, карточка
   открывает `ReelDrawer` этого рилса.
3. Облачко видно на `/`, `/history`, `/radar`; панель открывается/закрывается, Esc работает.
4. История переживает перезагрузку, «Очистить» стирает.
5. Стоимость одного вопроса видна в интерфейсе и в логе, ≤ 1 ₽ на типовой вопрос.
6. Импорт не сломан: rate-limit импорта не задевается вопросами чата.
