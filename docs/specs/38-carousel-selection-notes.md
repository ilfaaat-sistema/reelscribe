# Заметка с идеей к отобранной карусели

26.10.2026. ТЗ утверждено пользователем: «ок реализуй». Реализация проверена, выпуск выполняется.

## Запрос и согласованное решение

При нажатии ♥ для добавления карусели в отобранные предложить небольшое окно, куда можно записать мысли и возможное применение публикации. Заполнение необязательно.

Пользователь26.10.2026 явно выбрал: «Общие, как отобранные — без нового входа». Заметки имеют те же права чтения/редактирования, что и нынешний общий отбор. Это проектное решение, не предпочтение для других приложений. Личные заметки, авторизация и разграничение пользователей в объём не входят.

## Проверенное основание

По коду выпущенной версии6ac8f63: `useSelectedCarousels` читает общий список при фокусе и раз в30секунд, записывает отбор через PUT/DELETE, защищает состояние от устаревшего GET. `carousel_likes` сохраняет snapshot, период и дату; снятие отметки меняет active=false и не удаляет строку. Заметки и версии заметки сейчас отсутствуют. Основная лента и отобранные используют общие CarouselCard/CarouselDrawer; переводы обложки и описания должны сохраняться.

Изучены frontend API/hook, backend API/service, миграции shared_carousel_likes и archive14d. Схема production в этом ходе не проверялась и не изменялась; перед реализацией миграции нужна фактическая сверка. Для проектирования хранения прочитан supabase/SKILL.md; обязательное правило пользователя для миграций имеет приоритет: файл вgit, проверка всех ожидающих миграций, штатный db push, без MCP apply_migration/прямой правки production.

## Основной сценарий

1. Пользователь нажимает пустое ♥ в сетке или просмотре. Выполняется существующее сохранение отбора. Сердце становится активным только после ответа сервера.
2. После успеха открывается компактное окно «Зачем сохранил эту карусель?» с автором/миниатюрой, одной многострочной областью и кнопками «Сохранить заметку» / «Не сейчас». Подсказка: «Что зацепило? Как можно использовать это в своём контенте?».
3. Карусель уже отобрана. Пропуск, крестик, Escape или закрытие пустого окна не снимают ♥. Пустой комментарий никогда не обязателен.
4. После сохранения показывается подтверждённый текст и статус «Заметка сохранена». Ошибка заметки не отменяет отбор; окно сохраняет введённое и предлагает повторить.
5. Окно автоматически появляется только после явного успешного добавления самим пользователем. Опрос, переход страницы, открытие ранее отобранной, отмена снятия и синхронизация с другим устройством его не открывают.

Окно не открывать при ошибке отбора. При быстром повторном клике не создавать второй запрос/второе окно. Если пользователь уже ушёл со страницы, не открывать окно поверх новой страницы из позднего ответа.

## Чтение и редактирование

- Одна редактируемая заметка на одну карусель; не тред комментариев. До3000 Unicode-кодовых точек, счётчик, переносы строк. Обычный текст, без HTML/Markdown, вложений, автоперевода и ИИ.
- В отобранных: отдельный блок «Заметка» с2–3 строками и кнопкой редактирования; для пустой — «Добавить заметку». Пустая заметка не занимает большой пустой блок.
- В общей ленте у уже отобранной карточки — отдельная компактная кнопка заметки с признаком наличия. Она не открывает карусель и не снимает ♥; не вкладывать её внутрь button карточки.
- В общем просмотре: полный текст заметки и «Добавить»/«Редактировать» для отобранной публикации. Заметку визуально отделить от описания автора и перевода. Дата изменения заметки не заменяет дату отбора.
- Существующий поиск отобранных дополнить текстом заметки; подпись/placeholder честно упоминают заметки. Сортировки оставить прежними. Фильтры «с заметкой», теги, несколько заметок, история версий и экспорт — вне первого выпуска.
- Повторное нажатие активного ♥ по-прежнему снимает отбор; для редактирования используется отдельная кнопка. Заметку при снятии сохранять вместе с неактивной строкой. Отмена снятия и повторное добавление возвращают прежнюю заметку. Удалить текст можно явно очисткой поля и сохранением; это не снимает отбор.

## Окно, черновики и доступность

- Desktop: окно около360–420px рядом с нажатой кнопкой, с ограничением по краям экрана. Mobile: компактная нижняя панель, поле и кнопки доступны при открытой клавиатуре; прокрутка длинного текста внутри панели.
- Одно окно редактора на страницу. При открытии из drawer учитывать уже открытый диалог: фокус и Escape обрабатывает только верхний редактор, после закрытия фокус возвращается к кнопке заметки, drawer остаётся открыт.
- При первом добавлении на desktop фокус в поле; на телефоне не поднимать клавиатуру до касания поля, чтобы можно было быстро выбрать «Не сейчас».
- Enter — перенос строки, Ctrl/Cmd+Enter — сохранить. Кнопки не меньше44×44, подписи для screen reader, отсутствие горизонтальной прокрутки на320px.
- Сохранение явное кнопкой; не отправлять запрос на каждый символ. Черновик хранить поID карусели в sessionStorage этой вкладки и памяти. Закрытие заполненного редактора сохраняет черновик с понятным статусом «Черновик на этом устройстве», но не выдаёт его за серверную заметку. При недоступном sessionStorage сохранять в памяти и предупредить перед закрытием с потерей текста.
- При повторном открытии предложить/восстановить черновик, сохранить его исходную note_revision. После подтверждённого сохранения очистить черновик. Черновики не синхронизируются между устройствами; закрытие вкладки может их удалить. Явная команда «Сбросить черновик» возвращает серверный текст.
- Пока запись выполняется, не допускать повторную запись. Сетевой сбой сохраняет введённый текст. Поздний ответ относится только к исходномуID; он не закрывает редактор другой карусели и не затирает новый ввод.

## Предлагаемый контракт хранения и API

Для выбранного общего доступа расширить существующую строку `public.carousel_likes`: `note text NOT NULL DEFAULT ''`, `note_updated_at timestamptz NULL`, `note_revision integer NOT NULL DEFAULT 0`. Ограничение размера вSQL иAPI, пустой/пробельный текст нормализуется в пустую заметку. Согласовать подсчёт Unicode междуJS иPython/SQL; сохранять переносы строк. Общий лимит строки/HTTP-тела задать отдельно от числа символов.

- GET списка и PUT отбора дополнить полями note/note_updated_at/note_revision. Старые строки возвращают пустую заметку; старые клиенты могут игнорировать новые поля.
- Отбор/повторныйPUT/снятие не изменяют note и её версию. Не помещать заметку в snapshot Instagram, не отправлять её в сервисы переводов.
- Новый PATCH `/api/radar/carousel-likes/{id}/note`: `{note,expected_revision}`. Ответ содержит id и актуальные note/note_updated_at/note_revision; клиент объединяет только эти поля, не перезаписывает snapshot/selected_at старым снимком.
- Новая узкая RPC выполняет сравнение версии и запись атомарно. Прямую запись таблицы клиенту не открывать. Проверять ID, active и размер на обеих границах. Права остаются общими в пределах согласованного текущего приложения; не представлять эти данные приватными.
- Неизвестный ID —404; неверные данные —422; недоступное хранилище —503. Если карусель уже снята на другом устройстве —409 с отдельным кодом, черновик сохраняется, автоматического повторного отбора нет.
- При несовпадении версии —409 с актуальным текстом/версией. Не перезаписывать молча: показать «Заметка изменена на другом устройстве», серверный и введённый варианты; «Взять сохранённый» или явно «Сохранить мой вариант» с новой expected_revision. Проверка повторяется и при втором конфликте.
- Повтор после потерянного ответа с уже совпадающим текстом идемпотентен: вернуть текущий результат без новой версии/даты. Пустой повтор аналогичен. Реальное изменение увеличивает версию ровно один раз.
- Синхронизация остаётся через существующие focus/30секунд; редактируемый черновик не заменяется опросом. Общий hook координирует note/selection мутации одногоID и защиту от устаревших чтений. По ответу PATCH не воскрешать снятую карточку.

## Приёмка

- Новое♥ → успешный отбор → один редактор. Пропуск/пустое закрытие сохраняют отбор; ошибка отбора не открывает редактор. Нет автоматического окна от опроса/undo.
- Добавить/изменить/очистить заметку,3000символов/превышение, Unicode/emoji/переносы, безопасное отображение HTML-подобного текста. Поиск находит заметку.
- Снятие/отмена/повторное добавление не теряют заметку. Источник исчез из отчёта — snapshot и заметка остаются доступны.
- Телефон/ноутбук: сохранённый текст читается обоими; конфликт версий не теряет ни один вариант. УстаревшийGET не отменяетPATCH, note PATCH не восстанавливает снятый отбор, неоднозначный сетевой исход повторяется идемпотентно.
- Черновик переживает закрытие редактора/перезагрузку этой вкладки; сетевой сбой/ошибка сервера/конфликт не стирают ввод. Уход со страницы и поздние ответы не открывают чужой редактор.
- Desktop1440 и mobile390/320: окно в пределах экрана, клавиатура не закрывает кнопки, Escape/Tab/возврат фокуса корректны, редактор поверх drawer не закрывает оба окна.
- Все исходные ID отбора, даты, снимки, обложки, переводы, поиск/сортировки, звёзды авторов, скрытие и возврат в ленту сохранены. Build/lint, существующие и новые целевые тесты PASS, итоговые скриншоты лично просмотрены.
