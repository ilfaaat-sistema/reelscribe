## Предпочтение пользователя и модели

Для этой задачи Astra используется только в крайних необходимых ситуациях, а не для штатных этапов или повторной полной проверки. Независимая проверка первоначального плана моделью `gpt-6-astra` уже выполнена; её замечания включены ниже.

- Основная текущая модель Codex: координация, прокрутка, общие состояния, интеграция, проверки и итоговая приёмка.
- `gpt-6.1-sol`, reasoning medium: одна ограниченная подзадача — автономный компонент сетки и его локальные стили по контракту ниже. Не передавать всю историю, секреты или реальные массивы данных; достаточно контракта, очищенного примера и адресных файлов.
- Astra: только при остающейся после воспроизведения и обычной диагностики сложной проблеме архитектуры, безопасности или противоречии результатов. Сначала описать конкретную нерешённую проблему; передавать узкий вопрос, не повторять весь аудит. Повторная штатная проверка Astra не запланирована.
- Дополнительные агенты для сборки, форматирования или механической сверки не нужны. Выбор модели не является утверждением о её цене или скорости.

## Результат и границы

1. При начале прокрутки таблицы или сетки верхние панели сворачиваются в строку высотой 32 px со счётчиком и кнопками панели, фильтров и смены вида. В таблице под строкой остаются закреплённые заголовки.
2. «Фильтры» непосредственно слева от поиска, выделены при открытой панели либо заполненных дополнительных условиях.
3. Четвёртый режим «Сетка»: превью 9:16; под каждым 👁 просмотры, ❤️ лайки, 💬 комментарии, 🔥 залётность. Таблица остаётся начальным режимом.
4. Общие данные, поиск, фильтры, сортировка, выбор записей, экспорт и существующие режимы сохраняются. API, БД, сбор данных и зависимости не меняются. Автопроигрывания нет.

## Этапы, зависимости и владение

### 1. Подготовка — основная модель, последовательно

Проверить git status и worktree, сохранить чужие документы. Создать постоянную ветку `module/results-grid` и worktree `worktrees/results-grid`, предварительно проверить занятость имён. Измерить исходную страницу и предоставленный скриншот перед UI-правками. Проверить доступность разрешённого браузерного инструмента. Зафиксировать контракт компонента до запуска исполнителя.

### 2. Две независимые части — одновременно, максимум два исполнителя

Основная модель владеет `frontend/src/pages/Results.jsx` и `frontend/src/index.css`: прокрутка, кнопка фильтров, управление поиском, исправление выбора строк, подготовка переключателя режимов. До завершения агента не изменяет его компонент и стили.

Агент `gpt-6.1-sol` владеет только новыми `frontend/src/components/ReelGrid.jsx` и `frontend/src/components/reel-grid.css`: компонент сетки и локальные стили. Не изменяет Results, общие стили, API, package manifests, lock-файл и документы. Передаёт результат, выполненные проверки и ограничения. При нехватке качества основная модель принимает подзадачу, без серии повторных запусков слабых исполнителей.

Контракт: default export `ReelGrid({ reels, onOpen })`; `onOpen(id)` открывает существующий ReelDrawer. Компонент импортирует свои стили с префиксом классов `reel-grid`. Поля: `id`, `shortcode`, `author_handle`, `views`, `likes`, `comments`, `er`. Загрузка, ошибки API, пагинация и выбор режима принадлежат Results; сетка не делает запросов списка. Существующий `thumbUrl(shortcode, 'm')` используется только для изображения. Все типы записей сохраняются.

### 3. Интеграция — основная модель, после завершения агента

Дождаться явного завершения исполнителя, проверить его изменения. Подключить `mode='grid'`, общие данные и `onOpen`, существующую кнопку «Показать ещё». Переключение вида не вызывает самостоятельную перезагрузку данных и не сбрасывает выбор/фильтры. В сетке действует та же компактная строка при прокрутке. Проверить целиком совместную раскладку.

### 4. Приёмка и доставка — основная модель, последовательно

Сборку и линтер можно запускать параллельно как независимые команды без агентов. Затем проверить поведение и итоговые скриншоты, исправить выявленное и повторить только затронутые проверки. Сверить каждый пункт этого документа. Подготовить к разрешённым мёржу и публикации; постоянные worktree и ветку не удалять.

## Детали реализации

### Прокрутка и состояние

- Declarative `onScroll` на контейнере таблицы вместо эффекта, пропускающего контейнер при первоначальной загрузке.
- Сворачивание при `scrollTop > 24`, раскрытие при `scrollTop <= 8`. Перед сворачиванием проверить, что диапазон прокрутки после увеличения высоты контейнера до высоты окна минус 32 px останется больше 8 px с запасом. Короткий список, теряющий прокрутку, остаётся раскрытым, без искусственного пустого места.
- Скрыть header, rtop, subbar, filtpanel, заметку сессии и настройки столбцов; скрытые элементы исключить из Tab-порядка. Заголовки таблицы закреплены, непрозрачны; горизонтальная прокрутка сохранена.
- Локальный CSS `body:has(.resview.compact) > #apps-bar` скрывает панель сервисов. `.app:has(.resview.compact)` получает `height:100vh; height:100dvh`. Общий apps-bar.js и inline `--apps-bar-h` не менять; восстановление происходит при исчезновении класса.
- Проверять геометрию при resize и обновлении данных. Эффективный compact возможен только при table/grid, отсутствии loading/error. Сбрасывать состояние при обычной загрузке, смене режима и сессии.
- Поиск: отдельное управляемое значение ввода обновляется немедленно, поисковый запрос — с текущим debounce 300 мс. Очистить таймер при размонтировании. Переход в чтение и обратно не теряет видимый текст.
- Checkbox строки переключается один раз; остановить всплытие клика input при сохранении onChange и клика по свободной области td. «Выбраны все» вычислять по наличию каждого текущего ID, не по равенству длин массивов. Семантику экспорта не расширять.

### Сетка

- Колонки по ширине viewport: 2 до 480 px, 3 от 480 до 767, 4 от 768 до 1199, 7 от 1200. Последнее уточнение пользователя от 18.10.2026: на компьютере семь карточек в ряд для более плотного обзора.
- Обложка 9:16, object-fit cover по центру, loading lazy; при ошибке — заглушка той же геометрии.
- Под обложкой статистика 2×2, сокращённые числа; er — множитель ×. Локально различать 0 и null; общий fmtV не менять.
- Открытие настоящей кнопкой, доступной с клавиатуры; доступное имя карточки и названия показателей, подсказки. Избежать переполнения карточек длинными значениями.
- Подписи и расшифровки остаются в ReelDrawer. Новый интерфейс выбора записей в сетке не добавляется; существующий выбор таблицы сохраняется.
- Переключатель четырёх режимов адаптировать под 320–390 px без горизонтального переполнения страницы.

## Приёмка

- Прокрутка после initial load и повторной загрузки; длинный/короткий список; открытые фильтры, заметка и настройки столбцов; resize; горизонтальный скролл. Нет циклов сворачивания, пустой полосы или недоступных controls после ошибки.
- Сетка: число колонок, четыре показателя, 0/null, недоступная обложка, клик и клавиатура, пустая выдача, ошибка API, догрузка.
- Регрессия: поиск через все четыре режима, фильтры, сортировка, выбор строк, экспорт, аналитика и чтение; выход со страницы восстанавливает навигацию.
- `npm run build`, `npm run lint`; DOM для фактов, финальные скриншоты широкого и мобильного экранов для вида. Сборка не заменяет визуальную приёмку.
- При предыдущей попытке браузерный инструмент вернул `No browser is available`. Это ограничение текущей проверки, не доказательство отсутствия браузера или авторизации. При реализации повторно проверить доступное состояние; при недоступности честно отметить незавершённую визуальную приёмку и конкретный минимальный шаг для её завершения.
