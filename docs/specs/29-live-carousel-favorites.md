# Живые избранные авторы каруселей

Текущий статус: опубликовано на основном сайте; полный месячный обход текущих шести авторов подтверждён. Фактический запуск по расписанию ещё не подтверждён. [Точка продолжения](29-live-carousel-favorites-state.md). Финализацию по module-flow исполняет существующая сессия модуля в постоянном worktree; root координирует и принимает. Прежние frontend и review исполнители завершены. Глобальные инструкции и настройки Claude не менялись.

Статус: уточнённое ТЗ, 20.10.2026. Основание: добавление Instagram-профиля по ссылке на `/radar/carousels?period=14d` с телефона или компьютера; сбор каруселей **только избранных авторов** за последние 14 дней и дальнейших новых публикаций. Пользователь разрешил добавление без входа любому посетителю. Большой исторический список из 586 авторов не становится живой очередью.

## Поведение

Итерация кнопок карточки: исходный пользовательский снимок 1900×690, первая карточка x17–455, обложка до y539, нижняя плашка y540–678; eye/heart/star занимали 34/44/34 CSS px и перекрывали текст обложки. Сердце и звезда перенесены CSS-якорями вправо на нижнюю плашку, кнопки 30 CSS px, символы 20 CSS px; справа зарезервировано место под них. В карточках уже 190 CSS px они располагаются вертикально, освобождая ширину текста. Фон/рамка/значок глаза ослаблены alpha, hover/focus остаются контрастными. DOM, отдельные sibling-кнопки, labels/disabled/selected и album-значок не изменены; данных и Meta эта итерация не касается. Реальный скриншот требуется до приёмки.

- Рядом с выбором периода есть кнопка «Архив · 586 авторов». Она открывает `period=archive14d&favorite=0`, сбрасывает поиск автора и ограничение NEYRO_SET7, сохраняя общие скрытия. Активное состояние показывает, что открыт полный исторический набор за 6–19 октября.
- В блоке «Избранные авторы» есть поле для `https://www.instagram.com/<username>/`, `https://instagram.com/<username>/` или `@username` и кнопка «Добавить». Вставка профиля на телефоне работает штатным paste. Адрес публикации, редирект, иной домен и некорректное имя отклоняются до записи. Одинаковый автор не создаёт новую задачу.
- Единый серверный список избранного виден на всех устройствах и во всех вкладках. Звезда карточки и «Убрать» меняют тот же список. Состояния автора: ожидает, собирается, обновлено, пауза Meta, недоступен, ошибка. Добавление подтверждается после серверной записи, даже если сбор ещё не начался. Ошибка записи не меняет отображаемый список.
- Существующие локальные избранные не стираются. Четыре исходных профиля входят в начальный серверный список. Если браузер хранит другие имена, интерфейс предлагает однократный перенос с просмотром списка. После успешного переноса `localStorage` остаётся резервной копией до явного отказа от неё.
- `period=14d` показывает скользящие последние 14 календарных дней по Москве, включая сегодня. По умолчанию включены **только общие избранные**. Переключатель «Все избранные» выключает и включает это ограничение без смены периода: в выключенном состоянии видны уже собранные карточки всех доступных авторов из live и сохранённых архивов в том же текущем окне. Сбор всех авторов при этом не запускается. Для исторического набора 6–19 октября остаётся отдельный пункт «Архив 6–19 октября» и явный URL. `period=7d` и его отчёт остаются доступны. Поле периода и даты ответа показывают фактические границы; устаревший снимок не выдаётся за текущий.
- Выбор «Только избранные», поиск, сортировка, скрытые авторы, карточка, листание и обновление работают для живого набора. Пустой результат отличает «автор ещё не проверен» от «проверен, каруселей нет».

## Хранение и API

- Отдельная публичная ветка GitHub `data/carousels-favorites-live` хранит общий список, checkpoint и карточки с CAS по SHA коммита; архивные таблицы и ветки данных не менять. У ветки есть marker и `vercel.json` с выключенным деплоем. Сервер FastAPI читает опубликованное состояние и записывает его существующим серверным `GITHUB_DISPATCH_TOKEN`; worker GitHub Actions использует свой `github.token` с `contents: write`. Значения токенов не попадают в ветку. Право существующего серверного токена на запись проверить безопасным тестовым добавлением после выката.
- `GET /api/radar/carousels/favorites` возвращает единый список и статусы; `POST` возвращает добавленного автора и идемпотентен; `DELETE /{username}` убирает его из списка. GET/POST каруселей принимают `favorites_only` (по умолчанию `true`, обратная совместимость прежних ссылок `period=14d`). Для выключенного фильтра объединяются готовые 7d/archive14d и live: сначала границы окна, дедуп ID с предпочтением live, фильтры автора/источника/скрытых, сортировка и затем пагинация. При недоступном архиве возвращается понятная ошибка, неполная выдача не представляется полной. Деталь `period=14d` ищет live, затем архивы с тем же приоритетом дубликатов и проверкой текущего окна.
- Публичная запись ограничена на сервере: максимум 200 активных авторов и 30 новых за московские сутки, что выше ожидаемого небольшого списка. Превышение возвращает 429. CAS и повтор при конфликте не дают параллельным запросам обойти предел или потерять запись. Нельзя передать произвольный URL серверу для загрузки; из ссылки извлекается только допустимое имя. Секреты и полные IP не попадают в отчёты.
- Удаление из избранного прекращает будущий обход автора. Уже собранные карточки хранятся до истечения окна и не удаляются сразу. Повторное добавление автора возобновляет сбор без дублей.

## Облачный сбор

- Отдельный GitHub Actions workflow каждые 15 минут читает **только общий список избранных**. Новый автор попадает в ближайший доступный запуск; уже проверенные авторы перечитываются примерно раз в час. Очередь сортирует по последней попытке и даёт не более пяти страниц Meta одному автору за запуск, чтобы длинный профиль не задерживал остальных. Одна активная сессия, возобновляемые курсоры и контрольные точки; сбой одного автора не останавливает всех. Работает без Mac и ручного запуска.
- Пока исторический недельный или 14-дневный GitHub Actions сбор активен, новая очередь пропускает обращения к Meta и проверяет снова в следующем запуске. Статус добавленного автора остаётся «ожидает»; общий лимит Meta не расходуется параллельно с историческим обходом.
- Используется действующий Instagram Business Discovery и только публичные профессиональные аккаунты, доступные этой интеграции. Личный, закрытый или недоступный профиль получает явный статус; API не обещает контент, который Meta не предоставляет. Платный fallback не включать.
- Сохранить защиту `x-app-usage` с паузой от 85%, обработку 429/`Retry-After`, ошибку авторизации 190, защиту от повторяющихся курсоров и дедупликацию ID. Обход не создаёт неограниченную частоту запросов из-за публичных добавлений. Чтение использует московские границы выбранных 14 или 30 дней; сборщик хранит 30 дней и очищает только более старые карточки.
- GitHub state и SHA кешируются внутри одного запуска; после каждой страницы карточки и checkpoint сохраняются одним CAS-коммитом. При конфликте состояние перечитывается и изменения объединяются. До Meta-запроса проверяется остаток лимита GitHub с резервом для сохранения; чтение опубликованного файла больше 1 МБ переходит на Git Blob по SHA.
- Новые секреты не потребовались: действующий серверный `GITHUB_DISPATCH_TOKEN` успешно записал тестовую строку в preview. Значение токена не читалось. Наличие и назначение существующих интеграций проверены без изменения их настроек.

## Порядок и приёмка

1. Проверить доступность Meta, GitHub и Vercel без раскрытия секретов. Удалённая Supabase имеет несовпадающую историю миграций; новую миграцию не применять. При недоступности инструмента не считать интеграцию отсутствующей.
2. В отдельной постоянной ветке/worktree реализовать изолированную ветку данных, API и тесты инвариантов публичной записи; затем worker и тесты очереди; затем интерфейс и мобильную компоновку. Владение файлами на этапах не пересекается. Исторические workflow/ветки и несвязанные пользовательские правки сохраняются.
3. Проверить старые 7d/архив 14d, фильтры и скрытие, новые статусы, идемпотентность, параллельный лимит, восстановление после лимита Meta, сборку и узкий экран. По возможности проверить живую страницу скриншотами до/после.
4. После разрешённого деплоя добавить профиль с телефона или в узком viewport, подтвердить запись через повторное открытие с другого устройства/сеанса, ближайший запуск Action, сохранение checkpoint и появление карточки либо честного статуса «нет доступных каруселей». Если внешние проверки недоступны, назвать конкретное неподтверждённое звено.

## Риски и ограничения

- URL страницы не является защитой. Любой посетитель с адресом может добавить или убрать автора в общем списке; лимиты сдерживают расход, но не устанавливают владельца. Изменение этого правила потребует входа или отдельного права на запись.
- Нынешний снимок за 6–19 октября нельзя автоматически продолжать как живую очередь: фиксированы даты, список 586 и контрольная точка. Он остаётся архивом.
- В текущей сессии `devtools_*` отсутствуют, а локальный MCP `devtools` выключен; это не подтверждение отсутствия установки или авторизации. GitHub и Vercel проверены штатными CLI без раскрытия секретов.

### План месячного окна и реального сбора

Контракт: отдельный `period=30d` — последние 30 календарных дней по Москве, включая сегодня. Прежние 14d/7d/archive14d сохраняют смысл. Состав избранных и собранные данные не сбрасываются; сбор только бесплатный Business Discovery текущих избранных. Исторический gate завершён, поэтому после выката разрешён реальный запуск.

Существующая сессия модуля владеет изменениями frontend/API/helpers, backend/API, worker, их тестами и документом 29; корень координирует и принимает commit до merge. Порядок:

1. Общие границы окна worker/API, хранение 30 дней, версия checkpoint и маркер успешного полного backfill 30 дней. Старые 14-дневные проверки не ограничивают добор истории; далее почасовые инкременты.
2. 30d в selector/URL/API/detail и общем OFF-объединении готовых архивов; сохранить source/hidden/toggle/отбор. Живые 14d/30d перечитываются в видимой вкладке и по focus также после finished, с сохранением загруженного префикса и scroll.
3. Узкие тесты границ, старого checkpoint/last_checked, полного покрытия и обновления finished; build и preview. Перед merge передать commit/diff корню для независимой приёмки.
4. Разрешённый direct merge, Ready/domain и реальные ограниченные Actions-запуски текущих избранных. Учитывать cooldown/85%/429, не запускать платный fallback. Проверить по каждому автору количество, статусы, диапазон дат и checkpoint; незавершённое не объявлять готовым. Итоговое состояние сохранить одним заключительным commit, синхронизировать постоянную ветку; чужие локальные root-файлы сохранить.

Реализация: API и worker используют общий `rolling_window`, 30 дней хранятся в той же ветке данных. Checkpoint версии 2 содержит `history_days=30` и признак полного backfill; автор получает `history_days=30`/`coverage_version=2` только после успешного завершения. Старый успешный 14-дневный обход не ограничивает старт новой истории, частичный обход продолжится по курсору без прежнего часового `next_check_at`. Ошибки разрешений и 190 останавливают общий запуск с явной причиной.

Совместимость отбора без SQL: запрос `30d` сначала разрешает деталь месячного окна; только на границе существующей RPC `source_period=30d` отображается в прежний служебный live bucket `14d`. Исходные `timestamp`, `caption` и остальные поля снимка не меняются; подборка открывает сохранённый snapshot, повторный отбор умеет искать 30d. Для открытых живых 14d/30d после finished действует обновление раз в минуту и по focus/возврату видимости; в скрытой вкладке запросы не выполняются. Префикс и scroll сохраняются, архивные finished-страницы не опрашиваются.
