# Карусели выбранных авторов за 14 дней

## Цель и границы

19.10.2026 пользователь выбрал 586 уникальных авторов из своей сохранённой истории. Все 586 уже входят в прежние 1600 авторов. Собрать их карусели за **6–19 октября 2026 включительно** в зоне Europe/Moscow и показать отдельным периодом в сетке. 19 октября — неполный день. Это снимок указанного периода, не скользящее ежедневное окно.

Подготовленный список лежит только локально в `../Материалы планирования/2026-10-19-карусели-14-дней/target-authors.json`. В публичный код не помещать источники выбора авторов. GitHub Actions должен получить список через закрытый secret `CAROUSEL_FORTNIGHT_AUTHORS`; публичный набор данных содержит результаты и технический checkpoint, поэтому состав выбранной группы может быть выведен из него. Передача списка во внешний GitHub Actions secret отклонена автоматической проверкой до явного разрешения пользователя; не повторять её другим способом. До согласования не запускать облачную очередь.

## Контракты

- Прежний набор 13–19 октября, ветка `data/authors-carousels-20261013-20261019`, workflow и отчёт остаются неизменными. Новый набор изолирован в ветке `data/authors-carousels-20261006-20261019` с отдельным marker, checkpoint и отчётом. Не менять даты в прежнем checkpoint: старый сбор остановил сканирование по границе 13 октября и пропустил бы 6–12 октября.
- Selection создаётся в GitHub Actions из закрытого списка имён и сохранённого seed списка 1600 с существующими данными подписчиков. Проверить ровно 586 уникальных допустимых имён, каждое должно входить в исходные 1600. Новое состояние начинается с пустым `authors` и нулём запросов.
- Автоматический сбор 14 дней не обращается к Meta, пока опубликованный недельный отчёт не получит `collection.status=finished`. После этого выполняется ограниченный пилот, проверка дат/типа карточек/отсутствия платных вызовов и автоматическое продолжение. Новая очередь также соблюдает существующие `x-app-usage`, cooldown, пагинацию и контроль checkpoint.
- API принимает `period=7d|14d` для списка и карточки. Пустой `period` выбирает 14 дней, если новый отчёт уже есть, иначе прежние 7 дней. Ответ всегда сообщает свои фактические `start_date`/`end_date`. Явный `14d` до первого отчёта возвращает понятное состояние ожидания; 7 дней доступно постоянно.
- Интерфейс показывает фактический период из ответа, предлагает переключение 7/14 дней и сохраняет поиск, сортировку, избранное и скрытых авторов. Ссылка на целевой набор: `/radar/carousels?period=14d`. У 14-дневного набора ровно 586 целевых авторов; отдельная публичная метка папки для каждого автора не нужна.

## Порядок работ и владение

1. Корневая сессия: инвентаризация источников, границы/приватность, ТЗ, подготовка закрытого списка, интеграция, проверка и запуск. Файлы: этот документ, приватный локальный список, GitHub secret, итоговая приёмка.
2. Модуль облачного сбора: только новая store-обёртка, seed/worker/gate, workflow и их тесты. Зависит от ТЗ; не меняет недельный collector и прежнюю ветку данных.
3. Модуль API/интерфейса: только `backend/app/api/carousels.py`, его тесты, `frontend/src/api/carousels.js`, `frontend/src/hooks/useCarouselFeed.js`, `frontend/src/pages/Carousels.jsx` и тесты API. Зависит от контракта period; не меняет файлы модуля сбора.
4. Корень ждёт оба модуля, собирает build/lint/тесты и проверяет интерфейс; готовит ревью. После явного разрешения на передачу списка выполняет внешние действия и проверяет запуск. Облачная очередь обращается к Meta только после завершения недельной.

## Приёмка

- 7-дневный URL возвращает прежние даты и не теряет существующие карточки; 14-дневный URL возвращает 6–19 октября и ровно целевую очередь 586 авторов после первого сохранения.
- Московские границы, страница с каруселью 6–12 октября, cooldown/resume и дедупликация проходят тесты; никакого платного fallback.
- Работа без Mac и терминала подтверждена активным GitHub Actions и сохранённым checkpoint. Пока недельный сбор не `finished`, новый job не вызывает Meta. Нагрузка контролируется прежним порогом 85%.
- На десктопе и узком экране видны период, карточки и детали; поиск, избранное, скрытие, листание и прежняя неделя работают.
