# ReelScribe

Сервис: берёт ссылки на Instagram Reels/посты → скачивает аудио → расшифровывает речь →
переводит иностранные на русский → подтягивает метрики (просмотры/лайки/автор/подписчики) →
показывает в таблице с аналитикой и отдаёт на экспорт.

Этот файл — конституция проекта. Подробное ТЗ: `docs/ТЗ_ReelScribe.md`.
Визуальный эталон UI/UX (макет, поведение, расположение): `reelscribe_v12.html` — открой в браузере и **повторяй его**.

Как строить этот проект современными инструментами Claude Code (субагенты, хуки, /goal, /code-review,
Supabase MCP) и как они работают — `docs/claude-code-toolkit.md`. **Перед первым применением любого
из этих инструментов сначала объясни мне его** (см. «Режим обучения» ниже).

## Стек
- Backend: **Python + FastAPI**, фоновый воркер на очереди. В проде — **3.12** (задан в
  `backend/.python-version`, им пользуются и Vercel, и GitHub Actions); локальный venv — 3.9.
  Код держать совместимым с обеими: везде `from __future__ import annotations`, без синтаксиса,
  появившегося после 3.9.
- БД: **Supabase (Postgres)**.
- Скачивание IG: каскад **одиночный Apify-актор (`APIFY_SINGLE_PRIMARY=1`, так в проде) →
  instaloader (по флагу `INSTALOADER_ENABLED`, нужна сессия) → StarAPI (RapidAPI, ротация
  ключей) → yt-dlp+ffmpeg** — везде только аудио. Профильный Apify-актор при
  `APIFY_SINGLE_PRIMARY` пропускается целиком: он стоит $0.041 за вызов против $0.0027 у
  одиночного и на старых сохранённых рилсах промахивается. Чем скачан конкретный рилс — видно
  в `info['source']` и в сводке воркера в конце прогона. Подробности и цены — §4 ТЗ.
- ASR: переключатель **`asr_mode`** (`auto | mlx | cloud | faster-whisper`): mlx-whisper на Apple Silicon,
  облачный API (OpenAI Whisper) на сервере, faster-whisper CPU как фолбэк.
- Frontend: **React + Vite**, без UI-кит-зависимостей сверх необходимого.
- Деплой: фронт и API — **Vercel** (один проект `reelscribe`, два сервиса: `frontend` и `backend`,
  один домен, конфиг `vercel.json`); воркер — **GitHub Actions** (`.github/workflows/worker.yml`,
  запуск по расписанию/вручную/мгновенно через `repository_dispatch`). Локальный воркер на Mac
  больше не обязателен для прода — нужен только для отладки; не держать его в бесконечном режиме
  одновременно с Actions (cooldown API-ключей после 429 живёт в памяти процесса отдельно у каждого).
  Секреты — только в env, никогда в коде и не в этом файле.

## Железные правила
- **YOU MUST: видео не хранить.** Качаем только аудиодорожку, после распознавания аудио удаляем. В БД — только текст и метрики. Исключение — раздел Радар (ТЗ 08): полное mp4 качается во временную папку функции Vercel на время одного разбора Gemini и удаляется в finally; в БД и хранилище видео не попадает.
- **YOU MUST: дедуп и кэш по `shortcode`.** Если у shortcode уже есть успешная расшифровка — НЕ скачивать и НЕ распознавать заново, брать из БД.
- **Зарубежные платные API разрешены** (решение 2026-07-03): StarAPI/RapidAPI, Apify, DeepL, OpenAI ASR — ок. Старое правило «без иностранной оплаты» отменено.
- **Auth не делаем** (решение 2026-07-03): доступ у любого, у кого есть ссылка — осознанно. Но **защита кошелька обязательна**: кап на количество ссылок за импорт + rate-limit по IP, потому что публичный сервис работает на ключах владельца.
- **IMPORTANT: скачивание троттлим.** 1–2 параллельно, паузы с джиттером между запросами, чтобы Instagram не блокировал. При блоке/ошибке — ретрай с backoff, затем следующий источник каскада (см. «Стек»). Первый источник — **одиночный Apify-актор** под флагом `APIFY_SINGLE_PRIMARY` (в проде включён), остальные добивают его промахи. Порядок менялся 19.08.2026: до этого первым был профильный актор, и документация об этом врала до 04.09 — если снова расходится с `backend/app/pipeline/download.py`, верить коду и править документ.
- Весь UI и заголовки экспортных колонок — **на русском** (в JSON-экспорте оставляем технические англоключи).
- Результаты показывать **рано**: после первой партии (~50) открывать таблицу, остальное догружать в фоне.
- Обработка по-рилсово изолирована: ошибка одного (приватный/удалён/нет аудио) не валит партию — помечаем `failed` + причина.

## Терминология и метрики (считать ровно так)
- `shortcode` — id рилса из URL `instagram.com/(reel|p|tv)/<shortcode>`.
- **Залётность** `er = просмотры ÷ подписчики`. Цвет: оранжевый ≥10×, зелёный 5–10×, серый <5×.
- **Лайки/подп** `lpf = лайки ÷ подписчики` (в %).
- **Комм/подп** `cpf = комментарии ÷ подписчики` (в %).
- **Вовлечённость** `eng = (лайки + комменты) ÷ просмотры` (в %) — доля посмотревших, кто отреагировал.
- **Текст поста** = `caption` (подпись автора). **Расшифровка** = `transcript` (распознанная речь). Это РАЗНЫЕ поля, не путать.
- Два уровня заметок: `note` у рилса (про одно видео) и `comment` у сессии импорта (про всю партию).

## Конвенции
- Backend: type hints везде, pydantic-схемы для API, бизнес-логика в `services/`, в роутерах — только валидация/вызов. SQL/доступ к данным — не в роутерах.

## Как строить с современным Claude Code
Эти правила — про то, *как* вести разработку, чтобы задействовать свежие возможности. Детали и
объяснения каждого — в `docs/claude-code-toolkit.md`.

- **Параллелизм через субагентов — но скромно (M1, 8 ГБ): максимум 2–3 одновременно.** Делю независимые
  части между субагентами: бэкенд-пайплайн ↔ фронтенд-таблица ↔ ASR/downloader-стратегии. Не запускаю
  веер агентов на тяжёлых задачах (faster-whisper/ffmpeg сами едят память).
- **Усилие под задачу.** Архитектурные и «думательные» шаги (интерфейсы стратегий ASR/downloader,
  модель данных, пайплайн) — `/effort high`, самые сложные — `/effort xhigh`. Рутина (бойлерплейт,
  правки по мелочи) — обычный уровень.
- **План перед крупным.** Перед большой фичей — сначала plan mode (план в ответ, без правок), сверяемся,
  потом исполнение.
- **БД — через Supabase MCP.** Схему, миграции и проверочные запросы делаю через подключённый Supabase
  MCP, а не руками вслепую. Перед DDL/миграцией — показать, что собираюсь выполнить, и дождаться «да».
- **Качество в конвейере.** Линтер/тесты гоняются хуками автоматически (см. `.claude/settings.json`).
  Перед коммитом и перед деплоем (пуш в `main` = автодеплой на Vercel) — `/code-review` (на сложных местах `high`), фиксы применить.
- **Автономная добивка.** Когда цель чётко измерима (например «все критерии приёмки MVP из §15 ТЗ
  выполнены и тесты зелёные») — использую `/goal`, чтобы доработать через несколько ходов без ручного
  пинка на каждом шаге.
- **Крупные рефакторы — динамические воркфлоу** (`/workflows`), но только когда задача реально большая
  и разбивается на десятки шагов; для обычных фич это избыточно.

## Порты дев-серверов — закреплены за проектом

За проектом закреплён блок **5240–5249**. Внутри блока распоряжаемся сами (фронт, бэк, воркеры,

| Что | Порт |
|---|---|
| Фронтенд | **5240** |
| Бэкенд | **5245** |

```bash
npm run dev -- --port 5240
```
Фронту, который ходит в свой бэкенд, нужен `VITE_API_URL=http://localhost:5245`.

**Дефолт vite (5173) не использовать** — его одновременно занимали пять проектов. Порт всегда
задавать явно.

**Процессы гасить только по своему PID.** Никаких `pkill`/`killall`: на машине параллельно живут
дев-серверы других проектов, шаблон убьёт и их. Кто занял порт — выясняется так:
```bash
lsof -nP -iTCP:<порт> -sTCP:LISTEN     # PID слушателя
lsof -a -p <PID> -d cwd -Fn            # из какой папки он запущен
```

## Радар (`/radar`)

Разведка по рилсам конкурентов разделом ReelScribe: сбор Apify (до 5 ников, 1–12 мес) → выбор → разбор через Gemini (расшифровка + видеоанализ, 30–60 с) → отчёт с таймкодами и раскадровкой. Доступен по адресу `https://reelscribe-ai.vercel.app/radar`, общий домен, общая БД Supabase, общий бэкенд.

API в `backend/app/api/radar.py`, бизнес-логика в `backend/app/radar/` (сбор, разбор, Gemini). Таблицы `radar_*` (конкуренты, прогоны, рилсы, анализы, задания) — миграции `0008_radar.sql` и `0009_radar_cron.sql`. Разбор — синхронный вызов Gemini прямо в функции Vercel (`backend` сервис); холодный старт вычисляется в лимит `maxDuration: 300` в `vercel.json`. Страховка: pg_cron `radar-jobs-tick` каждую минуту → `POST /api/radar/jobs/tick`, подхватывает зависшие задания (queued >2 мин или in_progress >6 мин). Лимиты по базе (не памяти): 6 прогонов в час, 100 заданий в сутки — параметры в `backend/app/radar/settings.py`. Полное ТЗ — `docs/specs/08-radar.md`.

## Общая панель «Мои сервисы» (`frontend/public/apps-bar.js`)

Полоса сверху со ссылками на все приложения владельца: Рилс Парсер, Рилс Радар, YouTube Радар,
YouTube Парсер, Чертоги, Telegram-бот. **Этот файл — единственный источник для всех приложений**:
ReelScribe подключает его сам (`frontend/index.html`), а Чертоги и YouTube Радар загружают его с
https://reelscribe-ai.vercel.app/apps-bar.js. Своих копий у них нет.

- **Поменять ссылки** — массив `APPS` в начале файла, потом commit и push в main. Vercel выкатит за
  1–2 минуты, панель обновится во всех приложениях без их пересборки. Адреса YouTube сейчас ведут
  на ngrok владельца (работает, пока включён ноутбук); при постоянном домене менять здесь.
- **Текущее приложение** определяется по `data-app` у тега script или по адресу (хост и путь);
  в SPA подсветка обновляется при смене адреса.
- **Цвет полосы** подбирается по фону страницы: 9 точек по экрану, только крупные блоки, фон-градиент
  тоже учитывается; пересчёт при смене адреса и темы. Раскладка неизменна: высота 30px, переменная
  `--apps-bar-h` на `<html>` для раскладок на `100vh` (в ReelScribe учтено в `.app`).
- Скрипт не ходит в сеть и не трогает хранилища — только рисует ссылки. Но он выполняется с правами
  страницы, куда подключён: в публичные сайты с чужими пользователями его не подключать (так решено
  для публичной версии YouTube Радара).
